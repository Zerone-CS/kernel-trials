# 实验规范

本规范约定怎样用本项目验证 Agent 方法，并使第三方能够理解结论。文中的 **MUST（必须）** 是符合本规范的必要条件，**SHOULD（建议）** 是应优先采用、偏离时需说明理由的做法。部分要求由服务实现，部分是研究者的实验纪律；“必须”不表示同账号开发模式已经在技术上阻止了所有违反行为。

配置教程见 [研发指南](../RESEARCH_GUIDE.md)，预算事实见 [评测规则](../EVALUATION_POLICY.md)，数据字段见 [报告规范](REPORT_SPEC.md)。

## 1. 术语与实验单位

| 术语 | 定义 |
| --- | --- |
| task | 管理员安装的一个固定题包及其评价契约 |
| condition | 一种方法/模型/工具配置，例如原始 Agent 或 Agent + 知识库 |
| repeat | 同一计划中的独立运行轮次，从 1 开始 |
| trial | 一个 task × condition × repeat，对应独立会话、工作区和预算 |
| experiment | 一组冻结计划和其中全部 trial |
| control | 配对比较的对照条件，不等于评分参考 kernel |
| reference baseline / tbest | 裁判冻结的已知参考实现及其独立标定数据，不是理论最优 |

研究者 MUST 以完整 trial 为结果单位，不能把同一次会话中的 check/bench 当成独立重复。`attempt_index` 是运行记录序号，不替代 `repeat_index`。完整算子 full MUST 与固定 shape 子题分开展示，不能把 full 当作第 16 个独立 shape 样本。

## 2. 开始之前冻结计划

研究者 MUST 在开始运行前记录：任务选择、轨道、control、所有条件、独立重复次数、预算、主要评价指标及失败/缺失处理规则。应提交或归档原始配置、方法资源摘要、代码版本和 CLI 版本。服务冻结的 manifest 是已接纳计划的依据。

比较方法的实验 SHOULD 保持模型、题包、starter、资源配额、工具权限、外部工具状态和环境相同，只改变待检验方法。若同时改变模型、工具、预算或数据，MUST 将结论限定为该组合变化，不单独归因于方法。

所有条件 MUST 使用同一轨道。需要研究两种起点时，应分别建 `from_scratch` 和 `optimize` 实验，并分别报告。默认预算为每场 20 次反馈、3600 秒任务时间；降低预算可以，但 MUST 预先统一并披露。

## 3. 方法材料与数据可见性

方法的指令、文件、知识条目、检索索引、工具版本和外部数据快照 SHOULD 可复现。项目自动摘要绑定提供给 trial 的指令文本与资源文件字节；外部服务会变化的内容不因有 `method_digest` 就自动变成不可变证据。

方法材料 MUST 在 trial 开始前固定。Agent 在 `./eval start` 成功后才应读取题目和方法、开始实现；研究者不能提前把本轮 kernel 解答写入工作区。使用目标任务的参考 kernel、优化轨迹、隐藏测试、输出值或直接解答时，MUST 如实声明这些材料对方法的可见性，不得称为无答案泄漏条件下的能力测试。禁止通过读写裁判文件或伪造反馈获取分数。

验证通用方法时，研究者 SHOULD 将方法开发任务与最终检验任务分开，记录是否根据检验结果继续调方法。若不断在同一批 shape 上调知识库，得到的是这些场景上的开发结果；需要新数据或预先隔离的验证任务来支持外推。

## 4. 独立运行与执行顺序

每个 trial MUST 从对应 starter 和新 CLI 会话开始，不继承兄弟 trial 的 kernel、反馈、答案或上下文。自定义 command 作者 MUST 保证新会话语义；仅启动一个新进程不保证用户记忆、缓存、上级指令和外部状态被清空。

内置驱动顺序为奇数轮按条件顺序、偶数轮反转。研究者 MUST 披露这是确定性轮换，不宣称随机化。若外部研究设计另行随机化或跨时段运行，SHOULD 保存顺序计划和设备状态记录。

同任务、同轮次不同条件共享隐藏输入种子，不同轮次变更种子；研究者 MUST 不读取或公布私有种子。公开性能用例仍使用冻结的测量协议。

## 5. 预算、恢复与终评

Agent MUST 只提交 `kernel.asc`，经 `./eval` 请求裁判编译、测试、计时和终评。固定工程载体、ABI、测试、基线和预算配置不是候选修改范围；kernel.asc 内的 Host 逻辑（如 tiling 和启动代码）遵循题目契约。固定 shape 专门化是题目允许的优化，但固定输入答案、跳过实际计算或读取参考输出不允许。

编译、执行和正确性失败消耗已受理反馈次数。研究者 MUST 不以“还没编译过”为由重置同场预算。唯一终评应选已有合法版本；任务结束后不能把未提交的新代码补入成绩。

网络不确定时 MUST 恢复原请求或原实验，不新建额外场次代替失败。`--new` 只用于明确的一组新实验；原计划和结果必须保留。进程状态不明时 MUST 先核实，不删除运行标记来规避拒绝。管理员恢复丢失 worker 前必须确认 worker 已终止，不能把恢复动作当作免费重新提交。

## 6. 指标与失败处理

报告 MUST 至少同时包含：计划 trial 数、已完成数、已验证最终正确数、候选失败数、未知/无效数、有效性能 pair 数及缺失原因。仅列平均分或成功样本的最快延迟不符合本规范。

| 情况 | 处理 |
| --- | --- |
| 最终编译、运行或正确性失败 | 保留任务 0 分，不生成性能加速比 |
| 没有终评 | 记录未知/`no_final_result`，分数为 null |
| 基础设施故障或测量无效 | 无有效性能分；不能直接归为 Agent 0 分 |
| 最终正确但未得到有效性能测量 | 可记录已验证正确，性能分仍不可用 |
| 对照与方法双方正确、计量有效且身份可比 | 可计算同任务同轮次性能加速比 |

配对 MUST 使用同一任务与轮次，不能把 control 的最快轮和 method 的最快轮拼接。合法失败的 0 分可参与分差，未知值不能补 0。加速比为 control / method，分差为 method − control；研究者 MUST 明确方向。

基于失败分数和有效分数的均值 MUST 同时标注有效数量与未知数量。不能把一次成功、两次未完成写成“成功率 100%”。首次公开正确只是过程里程碑，不是独立终评成功。

## 7. 可比性、统计与外推

题包、轨道、预算、参考基线、协议、计量引擎或环境不一致时，MUST 保留不可比原因，不直接合并。若失败提交没有实测环境而使用冻结基线绑定环境，MUST 保留该来源标记，不能声称失败版本已经跑过 NPU。

研究者 SHOULD 预先选择重复次数并使用所有计划结果。样本不足时报告观察事实和不确定性；不能仅凭一次加速或波动范围宣称统计显著。项目不实现显著性检验、置信区间、独立样本估计或多重比较校正。需要这些结论时，应另行设计统计分析，并披露假设、排除规则、效应量和多任务检验处理。

能力标签是重叠的场景描述。MUST 不把 Case8 在两个标签中的记录计为两份独立样本，不把单一 shape 收益直接推断为所有非对齐或大矩阵问题的能力改善。SHOULD 用未参与方法开发的任务、更广输入域或新算子补充检验。`full` 与固定 shape 的契约不同，应分别解释。

## 8. 最小公开披露清单

公开实验 SHOULD 附带可下载的脱敏配置、manifest、comparison 和所有 trial 摘要，至少披露以下项目：

| 项目 | 最低要求 |
| --- | --- |
| 研究问题 | 方法变化及预期改善的场景/指标 |
| 软件版本 | 仓库 commit 或完整源码摘要、CLI 版本、工具版本 |
| 任务与起点 | task IDs、包/协议摘要、track、starter 身份 |
| 方法 | 每个条件的说明、method_digest、资源来源、外部依赖、任务答案可见性 |
| Agent | CLI provider、配置声明的模型、权限和用户配置约定；区分声明与认证 |
| 预算 | 每场反馈/时间/终评策略，不能只报总运行时间 |
| 执行 | repeats、所有计划 trial IDs、顺序、重跑/恢复与排除说明 |
| 环境 | NPU 型号、CANN/驱动、计量引擎、协议、基线身份、设备使用约束 |
| 结果 | 正确率分母、失败/未知、有效 pair 数、分差、延迟与加速比、波动 |
| 限制 | 单算子与固定 shape 范围、开发模式、数据污染风险和统计边界 |

API key、会话 token、隐藏种子、私有 judge 状态、未经授权的模型日志及个人/服务器标识 MUST 不随公开结果上传。删敏应在**副本**上进行；保留私有原件和摘要以便审计，不能编辑裁判原始结果来改变结论。

## 9. 安全等级声明

当前结果 MUST 标为开发评测，不得删除 `not_cheat_resistant`、`rankable=false` 或把它们改成正式排名。提示词、文件摘要与独立工作区不能代替账号/OS 隔离。CLI 或模型提供方的 token、费用、模型名字也是声明字段，不是独立认证证据。

`entry_smoke` 只验证入口、裁判与报告链路；尤其当 starter 未修改时，MUST 不把其成绩当作 Agent 的实现或优化成果。已知限制与报告方式见 [安全说明](../SECURITY.md)。
